# 闻灯主图左右侧脸修复设计

## 目标

修复 `夜市百相簿-主工作流` 中闻灯身份基准错误的问题，并从用户确认的正脸图生成同一人物的左右 90 度侧脸。

唯一身份基准：

`系列-夜市百相簿/02-角色/闻灯/设定图/闻灯正脸确定/闻灯-脸部正面-成品_00009_.png`

## 根因

当前线上工作流把节点 `1112` 的 FLUX 纯文生图结果接到 `1303`，作为三视角的结构锚。纯文生图每次塑造的是新身份，因此后续普通 VAE img2img 无法恢复用户确认的闻灯面孔。所谓“身份锁”只有文本描述和 latent 重绘，不包含真正的参考身份编码。

## 实现

1. 将确认图上传到远端 ComfyUI `input`，使用固定文件名 `wendeng_face_confirmed_00009.png`。
2. 更新主工作流中现有 Kontext 参考图节点 `1027`，令其读取该文件。
3. 启用现有 Kontext 公共模型、CLIP、VAE、参考编码链路，以及左侧 90 度和右侧 90 度两条分支。
4. 保持 `ReferenceLatent` 机制：参考图同时进入 conditioning，采样以 Kontext 编辑方式执行。
5. 不再使用节点 `1112 -> 1303` 的纯文生图结果生成主图侧脸；旧普通 img2img 身份锁分支保留但静音，便于对照和回退。
6. 输出文件名前缀改为 `闻灯主图-左侧脸-成品` 和 `闻灯主图-右侧脸-成品`，下载到角色设定图目录。

## 参数

- 模型：服务器已有的 Kontext fp8 模型槽位。
- Guidance：`3.0`。
- 采样：`euler + simple`，`20` 步，`cfg 1.0`，`denoise 1.0`。
- 种子固定，便于复现。
- 提示词只要求改变头部朝向，并明确保持同一人物、五官、发型、服装、光线、背景和画面尺度。

## 验证

部署前验证工作流 JSON 的节点、连线、模式和目标文件名；部署后读回服务器工作流确认一致。分别仅提交左、右分支，确认两项任务成功且产物可下载、可打开。最后目视检查方向正确，并与 `00009` 对比身份特征；如某一侧明显换脸，只调整该侧编辑提示词或 seed，不改基准图。

## 回退

部署前保存服务器当前工作流快照。发生验证或生成失败时，将快照重新推送，且不删除现有本地产物。
