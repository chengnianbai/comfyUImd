## 一句话结论

**问题不在参数、不在锚图选择，在于「话术框架」放反了。**

- 正脸词的开头是 **「重新拍一张高级摄影照片」**（Regenerate … as a natural high-end photographic portrait）→ 模型**重画**，所以干净。
- 侧脸词的开头是 **「保持参考图的一切，只把角度转 90°」**（Preserve … as closely as possible / Keep the exact same … from the reference）→ 模型**照抄参考图**，所以把锚图 00009 的**炸毛头发 + 脸颊斑点 + 硬质感**整套搬过来，再顺手转个身。

两条支路喂的是**同一张锚图、同一套采样参数**，差别只有这句话术框架，结果就是一个"棚拍干净"、一个"旧稿翻拍"。这就是你看到的 2 类风格。

# 下一步的三条路（按成本排序）

## A. 先试「换 seed」——零结构改动，一次提交，约 90 秒
之前观察过"三轮改成不同词、斑点位置却雷同"，怀疑散点与固定 seed `20260920` 的噪声图案有关。
做法：左脸支路跑 3 个种子（如 20260920 / 11111 / 777777），一次提交并行出三张，直接看散点是否随种子变。
- 若随种子变 → 挑一个干净的种子即可，且可能与"换词"叠加使用；
- 若不变 → 坐实是锚图带出来的，直接上 B 或 C。

跑法：`python _exp_left_reframe.py run --seed 11111`（一次一个，或我改成一次提交多分支）。

## B. 加一道「低降噪重拍」pass —— 真正的节点改动（约 8 个节点）
核心思路：**把"造 90° 姿势"和"洗质感"拆成两道工序**。
正脸之所以相对干净，是因为它只做"重拍"（姿势照抄参考图）；侧脸现在是"从零造姿势 + 顺便造质感"两件事一起干，模型只能用自带的侧脸先验，于是脏。

接线（新增节点，id 取现版 `last_node_id + 1` 起，**只加不改**）：

| 新节点 | 类型 | 输入 |
|---|---|---|
| X1 | FluxKontextImageScale | image ← `1035`（左脸 VAEDecode 的输出） |
| X2 | VAEEncode | pixels ← X1，vae ← `1026` |
| X3 | CLIPTextEncode | clip ← `1025`，text = 清洗词（用正脸那套"重拍为高级摄影"的话） |
| X4 | FluxGuidance | guidance 3.0，conditioning ← X3 |
| X5 | KSampler | model ← `1024`，positive ← X4，negative ← `1030`，latent_image ← **X2**，seed 同，20 步，cfg 1，euler/simple，**denoise 0.35 与 0.50 两档各跑一张** |
| X6 | VAEDecode | samples ← X5，vae ← `1026` |
| X7 | SaveImage | prefix `闻灯主图-左侧脸-清洗-成品` |
| X8 | ImageFlip + SaveImage | 右脸同理（水平翻转 X6 输出） |

要点：起点 latent 用**左脸成品自己**（不是纯噪声），姿势由起点锁死，所以 denoise 只影响"洗"的力度，不会把 90° 转回去。这一步和今天下午 17:05 那次"1034 起点改 1050"的实验不冲突——那次是拿**正脸**当起点（姿势会被钉在正面），这次是拿**已经转好的侧脸**当起点。

## C. 换锚：把 1027 从 00009 换成已确认的干净正脸
`1027` 的 LoadImage 换成 `主工作流/闻灯Kontext统一正脸-成品_00010_.png`（11:11 那版，皮肤干净、胡茬极轻）。
- 好处：整组（正脸+两侧脸）质感一起变干净，最省事；
- 代价：**转头角度会退到 3/4**（今天 14:15 实测：锚=干净正脸 → 干净但只转 ~3/4；锚=00009 → 真 90° 但脏）。所以 C 单用不解决问题，**C + B 才是完整解**（用干净锚出干净底子，再用 B 把角度推回 90°）。

**推荐顺序：A（90 秒）→ B（1~2 分钟，两档 denoise 一次跑完）→ C+B 组合。**
