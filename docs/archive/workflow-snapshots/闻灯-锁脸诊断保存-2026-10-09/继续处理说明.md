## 已确认的问题

1. 原全身参考节点 1310 / 1330 / 1350 读取 `wendeng_id_front.png` / `wendeng_id_left.png` 等。这些文件实际上是 **1024×1792 大白画布上只有一小块头像**，正面连下巴都裁掉了。并不是完整母版。
2. 全身链是 `LoadImage → FluxKontextImageScale → VAEEncode → ReferenceLatent → KSampler`。`ReferenceLatent` 是生成参考，**不是像素锁定**。空 latent + denoise=1.0 是 Kontext 常见编辑结构，不能单独把 denoise=1 判成配置错误，也不能声称改成低 denoise 就能从胸像变全身。
3. 精修分支 1360–1368 从已生成全身裁头后，用 SDXL denoise=0.45 再画一次。它没有原始母版参考，且输出没有回接全身，因此无法修复全身身份。1360 的 UI 输入声明还残留 ImageScale 的字段，应核对与后端 ImageCrop schema 一致。
4. 本次原提示词运行日志出现 `612 > 512` 的 token 长度警告，但任务确实成功执行。不能把这个警告直接说成已证实截断或运行失败。
5. 本机没有加载 InstantID / PuLID / IPAdapter 身份节点（object_info 已查）。旧安装脚本的存在不代表节点已生效。
6. 原工作流实际有 128 节点、193 连线，计数器落后（已修）。端口与连线静态回查未发现断线。
7. 排版重叠已定位：1310–1317、1330–1337、1350–1357 三组卡片的坐标几乎完全相同。例如三个 LoadImage 都在 `[20100,300]`。这是真重叠，不是缩放造成的错觉。
