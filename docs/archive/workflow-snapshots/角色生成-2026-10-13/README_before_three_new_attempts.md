# 基于 ComfyUI 的故事与多媒体创作项目

本项目围绕故事创作与多媒体制作，组织小说、创作脚本、角色、场景、道具、音乐等内容，以及对应的工作流和产物。ComfyUI 是实现生成与处理流程的工具，项目以内容和素材之间的关联、复用及一致性为核心。

《夜市百相簿》是当前创作系列。现阶段重点验证角色“闻灯”的视觉素材；小说、脚本、场景、道具和音乐属于项目整体范围，各类内容的实现进度以实际文件和阶段记录为准。

## 创作内容

| 内容 | 在项目中的作用 |
|---|---|
| 小说与世界观 | 故事、人物关系、剧情与背景设定 |
| 创作脚本 | 将故事组织为可制作的场次、镜头、动作与对白；与 `_scripts/` 中的 Python 自动化脚本区分 |
| 角色 | 人物设定、身份母版、外观、服装、姿态与参考素材 |
| 场景 | 故事空间、环境、氛围与镜头背景 |
| 道具 | 叙事所需物件及其外观、用途和一致性参考 |
| 音乐与声音素材 | 配合情节、场景与情绪的听觉内容 |
| ComfyUI 工作流与自动化 | 实现相应素材的生成、处理、验证与保存，保留可追溯的参数和运行证据 |

内容设定为素材制作提供依据，确认后的素材供后续制作复用。不同类别需要各自适用的模型、节点和验证方式；具体工作流按任务建立与核验。

## 当前角色工作流使用的模型

当前通用 [角色生成.json](系列-夜市百相簿/02-角色/角色生成.json) 使用 `FLUX1\flux1-dev-fp8.safetensors` 一体化 checkpoint，核心节点 8 个、连线 10 条；已核对模型下拉项和 17,246,524,772 字节大小，两次正面全身运行成功，精确权重 SHA-256 未核验。参考图目前仅转为文字描述，未接入图像条件。该链能出完整全身，但发型/双眼皮/眉型及扎腰尚未达标，不代表已验收。

下表为旧闻灯专用链历史配置，按 2026-10-13 本地 [闻灯.json](系列-夜市百相簿/02-角色/闻灯/工作流/闻灯.json) 的加载节点与实际连线整理，说明当前配置和用途。云端文件是否存在、内容是否一致，需在当前实例核验。

| 模型 | 工作流中的文件名 | 作用 | 使用位置与状态 |
|---|---|---|---|
| FLUX.1 Kontext dev（预期为 fp8_scaled） | `FLUX1\flux1-schnell.safetensors` | 结合提示词与参考图生成角色全身，并用于侧身、背面变化；参考条件不保证原脸像素或身份完全不变 | 节点1024；当前正面、侧面、背面默认输出的生成模型。现存权重身份待核验，见下方说明 |
| T5-XXL（FP8） | `t5\t5xxl_fp8_e4m3fn_scaled.safetensors` | 将详细提示词编码为 FLUX 生成使用的文本条件 | 节点1025，与 CLIP-L 配套，参与当前默认全身链 |
| CLIP-L | `clip_l.safetensors` | 提供 FLUX 使用的另一组文本编码，与 T5-XXL 共同构成文本条件 | 节点1025，`DualCLIPLoader` 使用 `flux` 类型 |
| FLUX VAE | `FLUX1\ae.safetensors` | 在图像与潜空间之间转换：编码参考图、解码采样结果 | 节点1026；参与当前默认全身链，负责编解码 |
| 4x-UltraSharp | `4x-UltraSharp (1).pth` | 对生成图像进行4倍放大；当前全身输出随后缩回0.5倍，得到净2倍尺寸 | 节点1018；参与当前正、侧、背面输出，放大不等于已确认细节真实或身份一致 |
| LEOSAM HelloWorld XL 7.0（SDXL） | `leosamsHelloworldXL_helloworldXL70.safetensors` | 提供 SDXL 的生成模型、文本编码器与 VAE，用于保留的脸部生成、重绘与精修分支 | 节点1002；保留在主图中，当前默认全身输出不依赖该加载节点，不自动重跑已确认脸部 |

Kontext 文件名说明：历史安装为绕过 ComfyUI-Manager 白名单，借用了 `flux1-schnell.safetensors` 槽位，下载目标为 `flux1-dev-kontext_fp8_scaled.safetensors`。这是安装记录，**尚未确认云端现存文件的真实内容**；不能仅凭借用文件名判断正在使用原版 Schnell，也不能把安装记录当作权重已核验。核验依据与停点见 [D16](docs/decisions.md#d16--kontext安装使用schnell白名单文件名) 和 [handoff](docs/handoff.md)。

当前主图没有 LoRA 加载节点，默认全身链也未配置 InstantID、PuLID 或 IPAdapter 身份模型。脸部参考通过 `LoadImage → VAEEncode → ReferenceLatent` 提供；`ReferenceLatent` 是参考处理节点，不是另一个模型。一次运行实际加载哪些模型取决于提交的输出及其依赖；默认三视角配置不表示每轮都会同时运行三视角。

## 模型补充评估与待确认建议

素材目标未达时，先检查实际输入、模型内容和条件链，再评估是否需要新模型、LoRA 或配套依赖；主动向用户反馈，评估结果在此原位更新。具体流程见 [workflow](docs/workflow.md#目标未达与模型补充评估)。下表为需求评估，候选不代表已下载、接入或验收。

| 目标/问题 | 当前依据与阻碍 | 是否补充模型或文件 | 状态 |
|---|---|---|---|
| 系列全身先行；闻灯发型、双眼皮/眼窝与眉型、清晰度 | 已建 8 节点 FLUX dev 文生图链；第二张提高至1024×1536、28步且核对history实收输入，头脚完整、清晰度已获用户认可，仍有发型分缝、眼窝/双眼皮与眉型不贴参考、背心未扎腰及前臂肤色不一致；用户要求减少黄黑、自然偏白。两张参考没有接入图像条件 | 暂不能认定缺模型。建议下一轮先评估图像参考/局部属性控制条件能否保留既有身体与亚洲身份；具体兼容节点和权重需定向核验，未选定或新增 | 候选03已准备但网关不可用，未运行；D23允许本轮最多3次（候选02计1次），仍失败提供具体模型/LoRA及预计安装时间，由用户决定安装 |
| 闻灯无袖扎腰、修长比例与放宽取景 | 已保存结果未达目标，提交提示词已核对；实际生成权重内容及条件链仍待核查 | 证据不足；先核验现有链路，再决定底模、LoRA 或控制依赖候选，尚无已确认新增清单 | 待评估；按当轮授权推进，不自动追加生成 |
| 闻灯严格侧身与身份一致性 | 既有侧身/融合验证未达要求，侧脸输入还存在媒体路径待核验项 | 先核验引用文件和参考链，再判断是否需要身份/姿态控制权重或其他方案；尚未选定候选 | 待评估，不能把参考节点称为硬锁脸 |

以上按已有实验记录整理，最新停点及证据见 [handoff](docs/handoff.md)。补充建议获对应授权后才能下载、安装、训练或切换；接入验证通过后，才同步上方“当前角色工作流使用的模型”表。
