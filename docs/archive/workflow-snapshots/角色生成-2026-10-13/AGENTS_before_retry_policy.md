# 项目入口与上下文预算

开始任务先说明目标、文件范围和验证结果。先读本文件与 `docs/handoff.md` 的“最小接续入口”，再按任务读取下列文档的相关章节；**不再默认通读五份文档**。新任务同样按需读取：

1. [docs/architecture.md](docs/architecture.md) — 整体架构、心智模型、关键设计原则。
2. [docs/decisions.md](docs/decisions.md) — 关键设计决策及原因。
3. [docs/workflow.md](docs/workflow.md) — 工作流程、协作偏好、命名规范。
4. [docs/roadmap.md](docs/roadmap.md) — V1/V2/V3 路线图、阶段完成清单。
5. [docs/handoff.md](docs/handoff.md) — 当前停点、恢复入口、已验证结果与接续步骤；固定维护这一份。

## 阅读规则

- 同任务追问、暂停恢复和上下文压缩沿用已读摘要，未变化的文件不重复读；重读先说明变更、冲突或缺失上下文的原因。不要复述完整历史、计划与已确认结论。
- 决策或生成任务必须读取相关角色决定、当前停点和验证约束；目录/保存位置变化查 architecture/workflow，阶段完成查 roadmap。索引只用于定位，不能替代相关约束正文。
- 需要委派时只传递目标、相关规则和文件，不默认复制全部历史；不为节省 Token 额外启动子任务。角色设定、工作流和图片均按需读取。
- `docs/archive/`、`docs/superpowers/`、`公共/技术归档/`、`公共/_归档/`、`_scripts/_wf/` 内的历史说明及带日期的交接记录，不是当前执行指令。只有追查具体证据时才读取，不因其中的“下一步”“开机即执行”等旧文字启动任务。

## 维护规则

- 用户最新明确指令优先；已决定的方案按 `docs/decisions.md` 执行。发现新证据或冲突，说明差异并更新对应条目，不擅自推翻已确认母版。
- 任务结束时，阶段完成状态同步到 `docs/roadmap.md`，具体停点与接续步骤更新 `docs/handoff.md`；新决策写入 `docs/decisions.md`。架构或协作方式变化时才更新另外两份。
- 系列通用角色初始生成工作流入口为 `系列-夜市百相簿/02-角色/角色生成.json`，用于闻灯及后续角色；验证 JSON 可以归档，主文件经用户验收后才能标记为通用最终档。云端保存或运行成功不等于已定稿。
- 原有 `系列-夜市百相簿/02-角色/闻灯/工作流/闻灯.json` 保留为闻灯专用历史工作流；新通用工作流不收敛、复制或合入该文件。后续角色默认复用 `角色生成.json`，不自动为每个角色新建同名工作流；只有确需专属工作流时才单独建立并明确用途。
- 每个角色的生成图片仍放在 `02-角色/<角色名>/设定图/` 下按任务命名的子文件夹。闻灯本轮用 `设定图/闻灯-角色生成示意图/`；该文件夹只放图片，JSON、API、运行记录与保存证据另放归档或工作流位置。
- README 只保留根目录一份作为项目导航；本文件负责智能体入口规则，不另建重复的 agent-spec。接续说明只维护 `docs/handoff.md`，不在保存目录继续新建“继续处理说明”。
- 不再为每次调参新建“作战计划”“待确认词表”“当前节点总表”。详细证据放在对应产物目录，必读文档只保留结论和链接。
- 不把“任务执行成功”“画面有所改善”写成“用户已验收”。不得把历史试验结论当成模型能力的永久定律。
- **目标未达时必须评估依赖是否合适或缺失。** 先按 workflow 的“目标未达与模型补充评估”核查实际输入、模型真身、节点和条件链，再判断是否需要新增/替换模型、LoRA、控制或身份参考权重等。主动向用户反馈依据、建议与待确认项，同步 README 的模型现状/补充建议；不能只反复堆提示词，也不能把一次失败直接归因于缺模型。下载、安装、训练、切换及工作流核心变更须有对应授权；已有明确授权不重复询问。

## Token 使用优化规则（长期适用）

### 定位与输出预算

- **每次工具调用前做预算检查：**本次文件是否已读？为何重读？要返回哪个章节/行段？所有并行结果合计是否不超过5000字符？任一项不明确时先缩小范围，不能把“新任务”当作通读全部文档的理由。
- 普通项目文档/代码读取优先使用 `_scripts/context_excerpt.py`，显式指定 `--heading` 或 `--start/--end`；禁止把 README 和五份核心文档一次全文输出。该工具对多文件合计限长，超限不返回正文；扩至10000前说明必要性。结构化文件继续用专门解析器。

- 先限定目录和扩展名，用 `rg --files` / `rg -l` 定位，再按函数或行范围读取、最小补丁修改。禁止默认全项目正文搜索；独立定位可合并执行，减少工具往返。
- 默认排除 `.git/`、图片、权重、缓存、日志、临时文件、构建产物、虚拟环境、`docs/generated/`、`docs/archive/`、`_scripts/_wf/`、角色 `设定图/`。明确目标后可以读取指定文件；不靠删除文件或修改 `.gitignore` 解决上下文问题。
- 普通文本单次读取范围不超过 **20,000 字符**；单次工具返回默认不超过 **5,000 字符**，必要时放宽至 **10,000 字符**并说明原因。多条并行输出合计也遵守预算。JSON 本地解析不受该读取上限限制。
- 在命令内部先限制输出，工具 `max_output_tokens` 只是第二层保护。`Select-Object -First N` 不能限制单行长度；长行 JSON/HTML 必须解析提取。不要先输出海量内容再依赖截断。
- Git 默认限定目标文件/目录；全局状态只返回计数，diff 只返回相关文本。日志先保存本地，再读关键错误、警告、退出码和必要尾部；禁止吞掉错误来缩短输出。

### ComfyUI 工作流增量读取与分析

- 先识别格式、大小、节点与连线数；沿用 `_scripts/diff_wf.py`，操作入口见 `docs/workflow.md`。比较基准为归档快照＋SHA-256，不能指向会被覆盖的主文件，也不代表用户已验收。
- 本地 Python 可以完整读取 JSON；模型默认只看变化节点 ID、字段路径、旧/新值、连线差异、一跳上下游和校验结果。Codex 修改也必须核对实际差异，不仅依赖计划中的修改清单。
- 只有基准和当前源哈希均匹配已验证记录、且没有外部依赖变化时，才跳过重复解析。用户在云端保存后先获取最新快照；本地哈希不变不能证明云端未变，也不能证明模型、插件或引用图片未变。
- 普通参数局部分析；类型、ID、mode、连接、格式、关键依赖或意外大范围变化扩大复核。未知格式、冲突或损坏时停止推进，先查证；不猜测，也不盲目重新载入整个项目。
- 修改前备份；修改后校验语法、目标节点、端口及双向连线，检查未授权字段无变化。差异审核并再次核对哈希后推进基准，旧基准和完整增量留档；不擅自重建整图或修改业务代码/模型。
- 有 `prompt_id` 时优先查该任务状态，完整队列只在调度/取消等必要时查。图片默认仅取本轮需要目视判断的 1–2 张或对比图；需要时扩大，不能以省 Token 为由省略视觉验收。
- 用户说“云电脑开启”时只恢复已授权任务：核对本次网关和相关停点，用一次最小可用性检查定位；需要工作流时获取当前同名源并本地比较。禁止自动读取完整 `/object_info`、全模型清单、全历史任务、全部工作流/日志/图片，或全套文档。仅缺失节点、依赖冲突等具体证据触发定向扩查。

### 脚本复用与归档控制

- 新增 `.py` 前先按用途定位现有 `_scripts/` 工具，核对入口与副作用；归档脚本仅作证据，不默认执行。优先复用参数化入口，不能因新需求、日期或尝试序号复制 prepare/run 脚本。确有能力缺口时先说明缺口，再最小补充；可复用脚本放 `_scripts/`，单次轻量离线检查可用内联 Python，无需落成新文件。
- 同一连续任务沿用已有证据目录，不因每次追问新建一套归档。完整 JSON 仅按备份、候选运行、API 提交或异常追查的实际需要保存；每个不同版本保留必要副本，已存在的相同字节 SHA-256 快照通过路径引用，不再复制。不可变基准与修改前备份继续保留。
- 远端保存后仍完整回读并本地校验；与候选字节哈希一致时记录回读时间、哈希与一致结果即可，不再默认保存 remote_after 副本。哈希不同则保存实际回读和差异，查明原因后才能推进；不得只查本地哈希代替远端校验。
- 每个任务集中维护一份必要运行记录，按尝试记录目标、源/候选路径及哈希、节点字段增量、验证、prompt_id、状态、输出路径与错误；可引用已有差异/验证报告，不另造同内容文件。队列仅在调度需要时读取；相同队列和成功响应记录时间及摘要即可，异常保留足够原始证据。详细流程见 `docs/workflow.md`。
- 本规则约束以后生成行为，不自动清理历史文件，不批量重构已有工具。规则落地不等于脚本已自动去重；运行前仍需检查具体工具行为。

### 命令输出与阶段交接

- 独立阶段结束时更新 handoff 的 **200–400 字最小接续入口**：目标、完成项、关键文件/版本、修改、验证、待解决项及下一步。详细证据只链接，不复制计划/日志，不另建交接文件。
- 自包含阶段完成或话题转移后建议以该摘要开启新聊天；长任务在阶段边界交接，不机械按小时中断任务。不未经用户明确要求创建新聊天，不声称文档摘要已清除当前聊天历史。
- 完成后只汇报修改文件、关键差异、验证结果和剩余问题；不重复输出完整文件。关键正确性/安全检查优先于预算，超限时解释并分段提供必要证据。
- 用量记录存 `docs/generated/token-usage.jsonl`，默认只看最新记录或聚合。分开记录本地读取文件数/字节数、工具返回字符/字节数、平台实际输入/缓存 Token 和来源；未知填 null，禁止按字节推算实际 Token 或将缓存重复计入总输入。
- 只有同口径的实际用量统计才能证明 Token 降低。工具输出限长只证明新增文本受控，不涵盖历史聊天、系统指令、技能目录或图片 Token；项目规则不能控制平台自动注入的上下文。
