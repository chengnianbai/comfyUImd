# 工作流程与协作约定

更新：2026-10-13。

## 开始一个任务

1. 根会话读 `AGENTS.md` 与 handoff 的“最小接续入口”，按任务定位五份文档的相关章节，记录当前母版、有效决定和停点；不默认通读全部。
2. 判断本次任务类型，只读相关资料。文档整理不需要连接云端或启动生成；做角色内容时才查该角色设定。
3. 继承用户在同一任务中的补充要求，不能因追问或上下文恢复而忘记原目标。已决定的母版、服装不反复询问。

同任务沿用已读摘要，变化时只核对相关部分；新任务同样按需读取。预算和阶段交接以 AGENTS 为准。

文本入口：`python -B _scripts/context_excerpt.py docs/handoff.md --heading '最小接续入口'`；精确章节或 `--start/--end` 行段必须显式指定，多文件共用5000字符预算，超限不返回正文。调用前按 AGENTS 检查已读状态、重读原因、范围和输出预算。云电脑开机只恢复已授权停点，按最小源状态与增量检查接续，不启动全量环境采集。

### 工作流增量工具（离线、只写报告与状态）

入口：`python -B _scripts/diff_wf.py`。目前支持本项目 UI 0.4 格式；API JSON/新格式需单独核验，不能套用“无变化”。先获取最新保存源；本地工具不会自动查询云端、检测浏览器未保存编辑或核验模型文件。

```powershell
# 首次或从 v1 升级：已核验快照 → 新 v2 状态；不要覆盖既有状态
python -B _scripts/diff_wf.py --init-state <已核验快照.json> --state <新状态.json>
# 每轮分析：完整差异落盘，控制台默认最多 5000 字符
python -B _scripts/diff_wf.py --state <状态.json> <最新快照.json>
# 审核差异与必要验证后推进；结构变化还需 --expanded-reviewed
python -B _scripts/diff_wf.py --state <状态.json> <最新快照.json> --advance --reviewed-sha <已审核SHA256>
```

基准保存为不可覆盖的散列命名快照；v1 状态保留追溯，v2 使用独立状态入口。报告默认位于 `docs/generated/workflow-diffs/`，可用 `--report <新文件>` 指定；不要在聊天中打印整个报告。默认输出最多30项字段，`--max-chars` 可设600–10000。超过四分之一节点且至少11个节点受影响时标记扩大复核；该阈值只触发复核，不代表此前变化均安全。

每次调用追加 `docs/generated/token-usage.jsonl`：文件数、读取次数/字节数、控制台字符/UTF-8字节数；只统计本工具，不覆盖其他命令或整个聊天。实际 Token 默认 null；有平台记录时可带 `--input-tokens`、`--cached-input-tokens`、`--usage-source <请求ID或统计来源>`。同一请求只登记一次；跨多次调用的小时总量单独记录，不能分摊后重复相加。缓存 Token 是总输入的子集。用量按可比较阶段分析，不以字符限长替代真实节省统计。

## 协作方式

- 使用中文，先说明发现或结果，随后说明证据、限制与下一步。
- 用户说“帮我处理”“顺便整理”即在相应范围内执行；常规可逆整理不额外索要确认。
- 只有实质缺失信息、决定冲突或不可逆操作才提问；先完成不依赖答案的工作。
- 不把用户已确认的人脸当作可随意优化的草稿。采用新母版、宣布图像定稿，需要用户明确确认。
- 用户要求“先保存/准备关机”时，停止继续扩展测试，保存能恢复的内容；不声称已替用户关闭云实例。
- **有限自动调试（2026-10-13 用户更新）：同一轮目标最多运行3次。** 每次生成后目视核验并说明差距，未达标可继续第2、第3次调整；已达标则提前停下供用户验收，不为用完额度继续生成。更换编号或恢复连接不重置计数，未提交的离线准备不计生成次数。第三次仍不行，停止生成并评估新增/替换模型、LoRA或参考控制依赖；明确具体名称、版本/文件、用途、兼容性、大小，以及下载、安装和首次验证的预计时间与估算依据，再由用户决定装不装，不自行安装。

## 修改与生成

1. **先核对事实。** 在线操作读取当前网关的工作流、队列和所需节点。逐项核对引用图片与本地母版，必要时比对 SHA-256。
2. **先留备份。** 从本次读取的工作流构建最小修改，保留用户已有改动。不要默认运行 `build_master_wf.py` 或会调用它的旧一键流程。
3. **限定验证范围。** 选择需要的输出支路及其依赖；不随手重跑已确认脸部。先用草稿确认身份和构图，再考虑放大。
4. **做可比较的实验。** 一次改变一个主要变量，记录 seed、输入、API JSON、prompt_id 和输出。分开判断能否运行、视觉效果、用户是否认可。
5. **目视验收。** 看整图检查头脚、站姿、比例；以不拉伸的相同比例裁切比较母版与输出的脸；以局部原尺寸检查发丝和皮肤。不能只凭文件名或指标下结论。
6. **同步与回查。** 写回前再次核对线上是否被用户修改；写回后读取验证，保存本地 JSON。说明需要重新打开工作流时，不覆盖用户浏览器未保存修改。

运行前确认真实节点和模型文件。标题里写“锁脸”、目录里存在安装脚本或下载队列显示结束，都不是依赖可用的证据。

### 目标未达与模型补充评估

此规则适用于角色、场景、道具、音乐等 ComfyUI 制作任务。发现结果未满足明确目标时，即说明差距并评估，不必等反复失败；判断范围限定在本轮目标与相关依赖，不自动启动全模型扫描；追加生成仅限上述3次预算与已授权范围。

1. **排查实现问题。** 核对任务收到的实际输入、引用素材、模型真实内容/版本、节点支持和采样/条件链；检查不一致、冲突或缺失。未知项如实标记，不能把安装历史或文件名当作已验证能力。
2. **判断能力缺口。** 说明现有配置能否继续实现目标，是否需要新底模、LoRA、ControlNet、身份参考权重、编码器/VAE、其他配套文件或自定义节点。区分“无需新增”“建议验证候选”“明确缺失依赖”“证据不足”；生成成功或单次视觉失败都不足以证明模型适用/不适用。不要把所有问题都归为LoRA缺失。
3. **主动反馈。** 给出未达目标、已查证事实/未知、推荐方案及依据。提出具体候选时核对可信来源、精确版本/文件名、用途、底模和节点兼容性、文件大小/显存/存储与必要使用许可；给出下载、安装、首次加载验证的时间范围及网络/GPU等估算依据，未知项标待核验。比较继续使用现有方案与补充依赖的代价，说明哪些已确认资产可能受影响。
4. **更新 README。** 维护“模型补充评估与待确认建议”，记录目标、现有阻碍、是否需要补充及候选/作用、状态，并链接 handoff 的证据。候选不写入“当前使用模型”表；只有实际接入并核验后才更新当前配置，用户确认可用后再注明验收。后续评估原位更新，避免为每次失败建新文件。
5. **按授权执行验证。** 无对应授权时不下载、安装、训练、切换或改核心链；先把推荐和最小验证方案准备好再请用户决定。已有授权范围内继续执行，遵守逐张检查、3次预算与停止约束。验证后回报结果并更新 README，失败或待验证候选不能标作可用。

## 节点排版

- 按“共享模型 → 母版输入 → 条件/处理 → 采样 → 输出”排列；正面、侧面、背面各自成行或分组。
- 说明与预览留足空间；历史/未使用节点集中安放，避免混入当前主线。
- 纯排版只调整位置、尺寸、分组、视口与可视走线路由；参数、mode、计算连线的变化属于功能修改，应单独记录和验证。可视路由不得改变 API 依赖图。
- 校验卡片矩形含标题栏不相交、分组包住卡片、ID 无冲突、端口类型正确。最后在浏览器中实际加载并检查显示。

## 命名与存放

| 内容 | 约定 |
|---|---|
| 系列通用角色生成工作流 | 位于 `系列-夜市百相簿/02-角色/角色生成.json`；闻灯和后续角色复用，验收前是工作文件，不能因保存/运行成功称为最终档 |
| 角色专用历史工作流 | `系列-夜市百相簿/02-角色/闻灯/工作流/闻灯.json` 只针对闻灯；新通用工作流不收敛、复制或合入此文件 |
| 已确认母版 | 保留原文件名，放在该角色的 `设定图/已确定脸部图/`；不自动覆盖 |
| 实验与候选 | 该角色 `设定图/<主题>-YYYY-MM-DD/`，可保留验证 JSON、API、任务记录和图片；图片示意目录可按任务单独建立且只放图片，明确用途，不称为最终档 |
| 保存与回滚 | `docs/archive/workflow-snapshots/<主题>-YYYY-MM-DD_HHmmss/`，保存修改前版本和本次校验；通过回读后更新本地正式文件 |
| 接续说明 | 固定更新 `docs/handoff.md`，不在保存目录新建日期说明 |
| 临时节点参数导出 | `docs/generated/`；仅按需生成，注明快照时间，不进入必读文档 |
| 退役说明 | `docs/archive/`；保留证据，不从旧“待办”恢复执行 |

日期使用北京时间。脚本优先从 `COMFY_BASE` 接收本次网关，不沿用失效地址。`_scripts/` 存在旧硬编码路径，未经评估不整体移动。

新角色自动复用系列通用 `02-角色/角色生成.json`；生成图片放在 `02-角色/<角色名>/设定图/` 的任务子目录。只有用户明确需要角色专用分支时，才在该角色目录下另建工作流；验证 JSON 可以保留，不能把图片目录混入运行记录。

已跑通且有用户认可结果后，沿用成功链路迭代。验证有效的改动维护在系列通用 `角色生成.json`，不合入旧闻灯专用文件。验收前如实标记“待验收”，验收后检查独立加载可运行且能对应已确认输出，再固定为交付入口。复用 JSON 本身不保证局部图像不变，身份保留仍须验证。

### 脚本复用与最小运行证据

1. 定位现有工具并核对参数、角色路径、当前网关和副作用。工作流比较沿用 `_scripts/diff_wf.py`；API 转换先核对 `_scripts/wf_api.py` 是否适配本次图。未经检查不运行旧脚本，不为每轮新建 prepare/run 副本；确有缺口时最小补充 `_scripts/`，无需新建通用框架。
2. 同一连续任务沿用证据目录。修改前读取当前源并核对版本：已有不可变快照的字节 SHA-256 与源一致且引用有效时，引用该快照作为备份；否则保存新备份。JSON 在本地完整读取与验证，模型只接收增量和必要关联。
3. 候选与 API 文件只在实际运行、提交或追查需要时保存。已有相同字节哈希文件可引用；UI 工作流和 API 格式用途不同，不强行合并。保存后完整远端回读并验证；与候选一致时记录时间、哈希和校验结果，内容不同或失败时保存原始证据及差异，停止推进并排查。
4. 优先补充该任务已有运行记录；没有时仅创建一份 `run_record.json`。分次记录目标、脚本入口、备份/候选路径与 SHA-256、节点/字段增量（或报告路径）、校验、prompt_id、状态、输出与错误。用任务 ID 查询结果；完整队列仅在调度排查需要时读取，不逐轮复制相同队列或成功 HTTP 响应。
5. 不限制必要备份、错误证据与正确性检查。哈希去重按字节一致判断；仅解析内容相同但字节不同，不能直接宣称原文件完全一致。基准更新仍按差异审核规则执行，运行成功不等于用户验收。

上述为新增产物的执行规则，尚未将历史脚本改造成统一运行器或自动去重工具；不删除既有归档，不批量改动业务代码。

## 保存与结束

- 保存母版来源、工作流、测试产物与执行状态。线上可访问时检查是否仍有运行/排队任务；无法核验就写明，不能把旧快照当现状。
- 写回成功并回读一致后，归档被替换的本地版本，再更新系列通用 `系列-夜市百相簿/02-角色/角色生成.json`。角色专用历史文件不自动改写。未核验的布局候选放归档目录，不冒充最新文件；只重命名或迁移已核验文件时校验散列，线上名称尚未同步则明确记录。
- `roadmap.md` 维护阶段完成清单；`handoff.md` 维护具体停点、最后核验日期、恢复文件、实验结论、下一步和待核验项；`decisions.md` 记录新决定与覆盖关系。
- 只有结构或协作方式变化时才更新 architecture / workflow。README 只维护导航，AGENTS 只维护入口要求，避免重复记录同一状态。
- 通用规范正文按用户最新决定维护现行要求，旧附录只作历史记录；具体覆盖关系写在 decisions，不在旧附录里制造第二套裁决。
- 不自动清理母版、历史图片、未提交修改或用户删除记录。不为低影响文档整理运行 GPU 测试或新增形式化测试文件。
