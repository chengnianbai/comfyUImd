# 项目架构

项目范围更新：2026-10-13。阅读与更新规则见 [AGENTS.md](../AGENTS.md)；具体执行状态见 handoff。

## 项目目标与边界

本项目基于 ComfyUI 组织故事与多媒体创作，涵盖小说、创作脚本、角色、场景、道具、音乐等内容及其工作流和产物。《夜市百相簿》是当前系列；角色“闻灯”的视觉素材验证是当前实施重点，脸部已确认，全身参考仍在验证。

小说与世界观提供叙事依据，创作脚本组织制作内容，角色、场景、道具与音乐承接视觉和听觉表达；ComfyUI 与自动化工具实现对应素材的生成、处理和验证。创作脚本指故事制作脚本，区别于 `_scripts/` 中的 Python 自动化代码。各类制作能力按实际模型、节点与工作流核验；未建立的流程不视为已完成。

当前目录以世界观与剧情、角色资产为主，其余类别尚无独立入口，不因范围说明自动创建新目录。角色出图调参时沿用已确认人物与剧情；内容创作任务按用户要求处理。具体资料按任务查阅。

## 心智模型

整体关系：故事与世界观 → 创作脚本及素材需求 → 角色、场景、道具、音乐 → ComfyUI 工作流生成与处理 → 验证、用户确认与复用。以下为当前角色视觉素材的具体流程：

```text
角色稳定身份与外形锚点 → 完整正面全身候选 → 用户确认整体形象
                                          ↓
                             左右侧 / 背面 / 斜侧面逐张验证
                                          ↓ 用户确认
                                多角度初始角色参考资产
                                          ↓
                          专属服饰、表情、道具与动作造型
```

初始阶段只从角色锚点读取稳定身份与外形，不读取专属服饰、表情、道具或动作。旧闻灯脸部母版保留作历史资产，新通用工作流不要求先从脸部扩出全身。当前还没有经过用户最终验收的新全身基准。

| 位置 | 职责 |
|---|---|

| `系列-夜市百相簿/02-角色/角色生成.json` | 系列通用角色初始生成工作流，闻灯及后续角色复用；验收前为工作文件 |
| `系列-夜市百相簿/02-角色/<角色名>/设定图/<任务名>/` | 该角色本轮图片；闻灯本轮 `闻灯-角色生成示意图/` 只放图片 |
| `系列-夜市百相簿/02-角色/闻灯/工作流/闻灯.json` | 闻灯旧专用工作流，保留追溯；新通用工作流不合入此文件 |
| `_scripts/` | 读取、转换、验证、运行和保存工作流的工具；旧脚本不等于当前推荐方案 |
| `公共/` | 通用素材规范和环境参考；其中技术归档按历史资料处理 |
| `docs/archive/workflow-history/` | 已退役的工作流说明，保留追溯，不作为行动清单 |
| `docs/archive/workflow-snapshots/` | 旧工作流、保存前后快照、API 请求、提示词备份及保存校验；按需追溯 |

新角色生成统一复用 `角色生成.json`，不合入旧闻灯专用工作流。角色示意图目录只存图片，验证 JSON 与运行证据另行归档；验收前如实标记候选，不能要求用户在多个实验文件间拼装最终流程。

具体节点和参数以**本次读取的线上 JSON**为准。离线使用 [通用角色生成工作流](../系列-夜市百相簿/02-角色/角色生成.json)，保存日期与来源见 [handoff](handoff.md)。不能按文件修改时间、版本号或文件名含“current”来选择母版工作流；旧 Markdown 和节点标题不能代替真实连线、参数与运行结果。

## 运行架构

- 本地 Windows 工作区负责整理资产、修改 JSON、保存与比较结果。
- 云端 ComfyUI 负责 GPU 生成。最后核验环境为 ComfyUI 0.30.1、RTX 5880 Ada 48G；开机后需重新检查服务与所需节点。
- 通用角色生成主文件为 `02-角色/角色生成.json`，云端工作流 ID 为 `1942ebf9-d94a-4790-bc94-ff98ed497520`；闻灯与后续角色复用。旧 `闻灯/工作流/闻灯.json`（ID `1ada4652-6b51-457f-a920-a88bf20ba27c`）为闻灯专用历史链，互不收敛。网关地址可能随开机变化，不写成长期常量。
- 主图包含默认停用输出的 SDXL 脸部历史链与 Kontext 全身参考编辑链。当前默认仅输出全身正、侧、背面：正面从完整脸部母版生成，侧面追加完整侧脸参考并沿用正面身体，背面沿用正面身体。已确认脸部生产过程不自动重跑。
- `工作流/验证/` 中的分段缩放候选 P 已退役，不同步为主图；侧面融合试验未通过。当前实验进度与恢复步骤以 handoff 为准。
- `ReferenceLatent` 提供生成参考，不是像素锁定。当前未核验到已加载的 InstantID / PuLID / IPAdapter 节点，安装脚本存在不代表功能可用。
- 节点 1024 的模型文件名为 `FLUX1\flux1-schnell.safetensors`，历史安装记录称实际内容为 Kontext。未重新核验权重内容前，不仅凭文件名替换模型。

## 设计原则

1. 已确认身份优先于提示词、画质增强和模型的默认审美。
2. 能运行、视觉改善、用户验收是三个不同状态。
3. 先追踪真实输入和连线，再调参数；对照实验一次改变一个主要变量。
4. 工作流 JSON、API 提交、结果图和执行记录能对应起来，才能复现。
5. 排版属于可用性：按共享模型、输入、处理、采样、输出组织，卡片不重叠；整理位置不应意外改变计算逻辑。
