# 无影灵构「公共模型盘」接入方案

2026-09-20 · 针对「平台预置了公共模型盘，为什么还要下载 Flux」这个问题

---

## 一句话结论

**模型盘是"复制源"，不是 ComfyUI 的扫描路径** —— 平台里"有" ≠ 工作流"能用"。

但你的 `M:\Comfyui` 极可能就是那块公共盘（和官方文档里 `wuying-pub/Comfyui/...` 的命名完全对上），
**可以让 ComfyUI 直接扫它** → 那么转头组那两个残件（Kontext 11.9GB + ae 0.34GB）**一次都不用重下**。

---

## 一、实测证据（直接问服务器，不是推断）

### 1) ComfyUI 实际会扫描的全部目录 —— 只有本机 C 盘

```
checkpoints       C:\ComfyUI\models\checkpoints   +  C:\ComfyUI\output\checkpoints
diffusion_models  C:\ComfyUI\models\unet  +  \diffusion_models  +  output\diffusion_models
vae / text_encoders / style_models / clip_vision / upscale_models / loras … 全在 C:\ComfyUI\models\ 下
```

**没有 `M:\`、没有 `wuying-pub`、没有任何额外路径。**

对照官方文档：模型盘要用「图形化连接工作站 → 双击*模型盘*快捷方式」打开 —— 说明它是
**桌面会话里的一个盘**，从来没进过 ComfyUI 的扫描列表。

### 2) 加载器下拉框实况（"能不能被 Load"只看这个）

| 节点 | 候选数 | 内容 |
|---|---|---|
| `CheckpointLoaderSimple` | 4 | 含 `FLUX1\flux1-dev-fp8.safetensors` ✔ |
| `UNETLoader` | **1** | 只有 `FLUX1\flux1-schnell.safetensors`（借槽位名的 Kontext） |
| `VAELoader` | **2** | 含 `FLUX1\ae.safetensors` |
| `StyleModelLoader` | **0** | ← **空目录**，Redux 要用它 |
| `CLIPVisionLoader` | **0** | ← **空目录**，Redux 还要它 |

→ `flux1-redux-dev` **不在任何一个下拉框里**，而且它依赖的两个目录都是空的。
**控制台"看得到"和 ComfyUI"加载得到"是两件事。**

---

## 二、三个 Flux 不是一回事（别混）

| 文件 | 类型 / 目录 | 干什么 | 现状 |
|---|---|---|---|
| `flux1-dev-fp8.safetensors` 17.25GB | 一体化底模 / `checkpoints` | 文生图、img2img | ✔ 在，冒烟 37 秒通过 |
| `flux1-dev-kontext_fp8_scaled` 11.90GB | 指令编辑 / `diffusion_models` | **转头、改朝向** | ✘ 残件（`file not fully covered`） |
| `flux1-redux-dev` | 图像提示适配器 / `style_models` | 拿图当提示词，出**变体** | ✘ 完全没有；还需 `clip_vision\sigclip_vision_patch14_384` |

**所以"再下载一个 Flux"这件事根本不存在** —— 底模本来就在服务器上。真正欠的只有 Kontext + ae。

---

## 三、那为什么还是去下了？（复盘，我的失误）

我之前走的是 ComfyUI-Manager 的 `install_model` 接口，从**魔搭公网**硬拉。
平台其实有三条更省事的路（官方文档明写）：

1. **缺模型弹窗里的「立即下载」** —— 模型库收录了该文件名时，弹窗右侧会有这个按钮，
   下完自动放进 ComfyUI 对应目录。
2. **工作站内浏览器 → 魔搭社区** —— 文档原文：
   > 请务必在工作站内打开浏览器访问魔搭社区，**不要在本地电脑上访问**，因为无影灵构已与魔搭社区
   > 实现**内网加速**，在工作站内下载可显著缩短模型下载时间。
   （还能按名字搜到**正确仓库** —— 我那次 404 就是手写了 `Comfy-Org/flux1-dev` 这个不存在的路径。）
3. **模型盘直接复制**。

★ 结论：**以后缺模型，先查平台模型库/模型盘，再从工作站里下公网 —— 不要再从外面调接口硬拉。**

---

## 四、方案 A（推荐）：让 ComfyUI 直接扫模型盘 —— 零下载、零占 C 盘

在实例上新建 `C:\ComfyUI\extra_model_paths.yaml`（和 `main.py` 同级）：

```yaml
wuying_pub:
    base_path: M:/Comfyui
    checkpoints: checkpoints/
    diffusion_models: |
        diffusion_models/
        unet/
    vae: vae/
    text_encoders: |
        text_encoders/
        clip/
    style_models: style_models/
    clip_vision: clip_vision/
    loras: loras/
    upscale_models: upscale_models/
```

盘符不是 `M:` 就改；斜杠用 `/` 比 `\` 稳，`M:\Comfyui` 一般也能认。

然后：**重启 ComfyUI 服务** → 刷新页面。
**生效判据**：`UNETLoader` / `VAELoader` / `StyleModelLoader` 下拉框里出现模型盘上的文件。

⚠️ 三个不打包票的点：
- 若模型盘是**桌面会话映射的网络盘**，ComfyUI 服务可能看不到该盘符 → 下拉框没变化就是此路不通，退回方案 B。
- 从网络盘加载 11.9GB 模型比本地盘慢（一次性加载，可接受）。
- 官方文档没写这个用法，不在支持范围内。

★ 但收益极大：**公共模型库整个（SDXL / LoRA / AnimateDiff / …）都会直接进下拉框**，
以后基本不用再为缺模型下过东西。

## 五、方案 B（官方流程）：从模型盘复制进 `C:\ComfyUI\models`

1. 控制台 → **模型库** → 搜关键字 → 点"存放路径"右端图标复制路径（形如 `wuying-pub/Comfyui/vae/wan_2.1_vae.safetensors`）
2. 图形化连接工作站 → 双击**模型盘**快捷方式 → 打开 `wuying-pub`
3. 地址栏粘贴路径（去掉文件名）→ 找到文件 → **复制** 到实例对应目录：
   - Kontext → `C:\ComfyUI\models\diffusion_models\FLUX1\flux1-schnell.safetensors`
     （**必须覆盖成这个借槽位名**，否则工作流引用对不上）
   - ae → `C:\ComfyUI\models\vae\FLUX1\ae.safetensors`
4. 重启 ComfyUI / 刷新页面

⚠️ **仍受磁盘限制**：C 盘现在只剩约 0.3GB，复制 11.9GB 一样写不进
→ 走 B 就必须先腾出 12GB（删 `checkpoints\FLUX1\flux1-dev-fp8.safetensors` 或控制台扩容数据盘）。
★ **方案 A 不受这条限制**（文件留在模型盘，不占 C 盘）—— 这是它最大的价值。

## 七、Redux 值得试吗？

Redux = **拿图当提示词**的适配器，官方定位是"保留原图特征（风格 / 构图 / 人物特征）生成变体"，
**对提示词几乎无感**，代价是饱和度会偏高。

对你的目标（"以 v23 基图生图"）方向是**对**的，比纯文生图靠谱得多。但要三件套齐：

- `flux1-dev` 底模（有 ✔）
- `flux1-redux-dev` → `models\style_models\`（✘）
- `sigclip_vision_patch14_384` → `models\clip_vision\`（✘）

且它给的是**变体**，不是"换朝向"；论"同一张脸"的稳定性，
**直接喂基图 img2img（denoise 0.30）仍是最强的一条**。

→ Redux 可以作为"以图生图"的**备选支路**加进 Flux 组，但优先级排在把 Kontext 修好之后。
