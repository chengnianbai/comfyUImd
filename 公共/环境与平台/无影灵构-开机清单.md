> 依据 2026-09-17 真实账单复盘：**开机 6.83 小时烧掉 399 豆（¥16），而真正跑图只有约 18 分钟**。
> 利用率 4.4%，**约 95% 的钱花在空转上**。这份清单的唯一目的：把空转砍掉。

## 一、计费速查（1X 档：32vCPU / 64GiB / RTX 5880 48G）

| 项目 | 数值 |
|---|---|
| 费率 | **58.38 豆/小时 ≈ ¥2.34/小时**（「核时算力」= 灵豆） |
| 起步价（最低消费） | **2 豆/次 ≈ ¥0.08** —— 开机保底，不是每次收 58.38 |
| 关机 | **0 豆**（仅扩容磁盘计费，赠送的 100G 系统盘 + 40G 数据盘不计费） |
| 断连 | ⚠️ **≠ 关机，照常扣费** |
| 换算 | 1 灵豆 = ¥0.04；1000 豆 = 40 元 ≈ 17 小时；灵豆有效期 1 年，别囤 |

**每分钟 = 0.97 豆 ≈ 4 分钱。** 心里换算用这个：开机一小时 = 一碗面钱。

## 二、开机前（本机做，全程免费）★ 这一步决定 90% 的成本

- [ ] **方案定死**：要验证什么、改哪个变量、预期结果是什么，写下来再开机
- [ ] **提示词改完**：所有要跑的文案在本机写好（拼成 JSON 或脚本参数）
- [ ] **能力先确认**（10 秒，最关键）：这台机器**有没有**你需要的节点和权重？
      缺能力就换方案，**不要靠调参数硬撞** —— 9-17 就是没查，三轮 img2img 全白跑
- [ ] **脚本可重入**：不依赖实例常开，掉线了能续跑
- [ ] **待裁决的事先裁决**（如 A/B/C 方案选择），别等开机后现场想

## 二、磁盘：先别花钱扩，优先用免费的公共模型盘

| 磁盘 | 容量 | 状态 |
|---|---|---|
| 系统盘 | 100 GiB（赠送） | ⚠️ 曾只剩 10.74GB，接近满会**导致开机失败** |
| 数据盘 | 40 GiB（赠送） | 装全套模型**必然不够**（Flux 16 + SDXL 6.5 + Kontext 12~17） |

- ★★ **免费方案（优先）**：灵构预置公共模型盘 `wuying-pub`，**用软链挂过来，0 占盘、秒完成**：
  `bash 2-灵构-挂模型.sh list flux` → `bash 2-灵构-挂模型.sh grab flux`
- 其次：清盘；或用 ComfyUI 的「缺模型 → 立即下载」自动落位
- 真要扩容：控制台 **工作站 → 更多 > 变更数据盘**；**10 的倍数**、单盘上限 2000GiB、
  ⚠️ **不可缩容**、⚠️ **扩容部分关机也计费**
- 详见 `无影灵构-磁盘扩容指引.md`

## 三、开机前 10 秒体检（防止「开了机但起不来」）

> 2026-09-18 用户报障：点开机、进度条走完、又变回关机。
> 官方定性为**开机失败自动回滚**，最高频原因是**磁盘写满**。
> 我们这台机器风险尤其高：`C:\ComfyUI\models` 虽是指向 D 盘的目录联接，
> 但**下载缓存 / ComfyUI 日志 / 临时文件仍写 C 盘**，而 C 盘只剩约 10.7GB。

- [ ] **灵豆余额够不够**（余额 0 或套餐过期 → 开不了机）
- [ ] **C 盘余量**（控制台看；接近满就先清理或扩容）
- [ ] **大模型都落在 D 盘**（不要写进 C 盘）
- [ ] 起不来时的顺序：再点一次 → 控制台扩容/清理 → 快照恢复 → 重建实例

## 四、开机中（只做必须联网 GPU 的事）

- [ ] 一次性批量提交：`run_wf.py` 支持**逗号多选分支**，一次提交多条，比反复提交省排队
- [ ] **一轮只留一个变量**（denoise 或 guidance，绝不同时动）
- [ ] **先草稿档验证方向**（28 步、无放大），方向对了再跑成品档
- [ ] 产物**每步落盘**：跑图 → 下载 → （当基图时）再上传。实例随时可能掉线
- [ ] 中间不要讨论方案、不要改文案 —— **要动脑就关机，本机想**

## 四、跑完立刻关

- [ ] 回**控制台**点关机（不是关浏览器、不是断连）
- [ ] 确认状态变为「已关机」
- [ ] 产物已全部下载回本地
