## ⚠️ 开机失败：进度条走完 → 自动变回「已关机」（2026-09-18 用户报障）

**现象**：点开机，进度条走到最后又变回关机状态，实例起不来。

**官方定性**（阿里云帮助中心《云电脑管理常见问题》→「云电脑开机、重启及唤醒异常」）：
这是**开机失败后平台自动回滚**，官方列出三类原因 —
① VPN 软件装了非 VirtIO 网卡（本环境不适用）② 安全软件拦截进程（不适用）
③ ★ **磁盘空间不足导致启动失败** —— 排查命令 `Get-PSDrive C | Select-Object Free`（Win）。
官方解决方案：**给系统盘扩容** 或 **用远程命令删掉不再使用的文件**；
Linux 类还有一套 hostname / resolv.conf / 防火墙 5912 端口的检测脚本；
兜底是**恢复快照或重建系统盘**。

★ **本项目的额外高风险项**：`C:\ComfyUI\models` 虽是目录联接指向 D 盘，
但**模型下载缓存、ComfyUI 日志、临时文件仍会写 C 盘**。
C 盘原本就只剩约 10.7GB，多次下大模型（Kontext 17GB 等）后极易撑满
→ 直接命中官方第 ③ 条。**每次开机前应确认 C 盘余量；大模型一律确认落在 D 盘。**

**排查顺序**（成本从低到高）：
1. 控制台看**灵豆余额 / 套餐有效期**（10 秒）
2. 控制台看**磁盘占用**、系统盘是否接近满
3. 再点一次开机（排除上次会话残留）
4. 换地域/档位重建实例，或从快照恢复

## ★ 存储资源：赠送额度 + 扩容规则（2026-09-20 查官方文档）

官方原文：**「购买工作站时，现赠送 100GiB 系统盘及 40GiB 数据盘，如部署的镜像大小小于赠送值，
则无需额外为磁盘付费。」** 我们数据盘 39.9GB ≈ 40GiB → **就是那块免费盘**。

- ⚠️⚠️ **超出赠送值的部分要单独付费，且关机也照收**（关机只停算力，不停磁盘）。
  和算力"关机免费"完全不同，**这是唯一一项关机后仍在走表的费用**。
- 扩容路径（灵构控制台）：**工作站 → 卡片右下角「更多 > 变更数据盘」→ 变更配置页
  选「变更系统盘 / 变更数据盘」→ 选或填目标容量 → 同意协议 → 立即下单 → 订购支付**。
- 限制：**扩容必须是 10 的倍数**；系统盘/数据盘**各自最大 2000 GiB**；
  ⚠️ **只支持扩容不支持缩容**，生效后不能变小 → 别一步扩太大。
- 扩容后系统里容量没变 → 需手动扩分区：Win `diskmgmt.msc` → 扩展卷；
  Linux `growpart /dev/vdb 1` + `resize2fs /dev/vdb1`。

## ⚠️ 查远程 ComfyUI 节点是否存在的正确姿势（2026-09-16 踩坑）

`/object_info/<不存在的节点名>` 返回的是 **`{}` + HTTP 200**，**不是 404**。
所以下面这种写法会**把所有节点都误判为存在**：

```python
try:
    oi = json.loads(get('/object_info/' + node))   # 不存在也返回 {}，不抛异常
    print('HAS', node)                              # ← 永远走到这里
except Exception:
    print('NO ', node)
```

**正确做法**：拉全量 `/object_info` 一次，然后 `'X' in d` 判断 key。

```python
d = json.loads(get('/object_info'))     # 一次拉全（本机 827 个节点）
print('EXISTS' if 'FaceDetailer' in d else 'MISSING')
```

同理，判断某类模型目录有没有被扫描到，看节点输入的 `options` 长度，
而不是看节点在不在。`options == []` 表示「目录被扫描了但为空」或「目录不存在」，两者需再区分。
